# WEFT / PPL Website Technical Implementation Specification V2.2

> 当前实施基线 · 2026-09-16
> 范围：V1 首页 + Master Canvas + 前端临时内容预览
> 部署：GitHub Pages 静态站点；无后台、CMS、登录或网站写入接口

## 1. 文档优先级与范围

本版记录用户确认后的当前技术约束，替代 V2.1 中与其冲突的范围、编辑、身份、内容来源、发布和验收规定。首先遵循项目 [AGENTS.md](../AGENTS.md)。

- 首页视觉目标：[ref/final.png](../ref/final.png)。
- 首页结构：[Homepage Summary V0.1](WEFT_PPL_Homepage_Summary_V0.1.md) 中的 Header、Hero、System Summary、Master Canvas、Production Proof、Footer。
- V1 仅首页完整内容；独立章节、Flow、Evidence 的完整正文与跨页转场延期。允许最小目标页面承接导航，不得声称章节已完成。
- 导航栏点击切换独立页面：`/`、`/systematic-thinking/`、`/design-innovation/`、`/next/`。不得调用 scrollIntoView、设置首页锚点或切换 Canvas 来替代页面跳转。
- Master Canvas 的三个视角控制器负责预览；独立 EXPLORE CTA 负责跳转对应章节。VIEW EVIDENCE 跳转 `/evidence/`，不是滚动到首页证据区。
- 未实现的目标页面可显示简洁的“内容尚未开放”说明和返回首页链接，使点击真正改变路由且无 404；不添加虚构正文。仅 BACK TO TOP 等明确页内动作滚动。
- 邮箱待提供，暂不显示 Contact 链接。真实生产截图待补，不可伪造。

保留 Next.js App Router、React、TypeScript、CSS Modules / SCSS Modules、GSAP / ScrollTrigger、SVG 和 Canvas 2D。使用静态导出，不依赖请求时服务端运行。

## 2. 对 V2.1 的具体取代

[V2.1](WEFT_PPL_Website_Technical_Implementation_Spec_V2.1.md) 保留为历史和交互设计参考，不再是当前总规范。

- 原 §4.4、§8–22、§74–82 的 Sanity、Owner、Studio、Draft、Preview、CMS Schema、Webhook 等流程不进入 V1。证据元数据、规范化标注坐标和内容/动画解耦原则继续适用。
- 原 §90–91 的 Sanity / Preview / Publish 阶段，替换为本版的本地内容与临时试编辑实现。
- 原 §94–95 的章节和路由转场延期；§97–99 的草稿、鉴权、缓存验收替换为本版的临时状态隔离验收。
- 原 §103 中禁止自研完整编辑系统的意图继续保留，但“禁止 custom editor panel / inline editor”不得用于否定本版明确允许的有限文本预览控件。
- 原 §105、§107–113 中的 CMS 冻结项、多页面完成标准、发布流程和 Master Spec 优先级由本版取代。旧文末“先接入 Sanity 再完成网站”的顺序不再适用。
- §23–73 中未与本版冲突的 graph/state/render 分层、动画归属、交互中断、移动端、无障碍和性能约束继续适用。Master Canvas 的 Preview 与内容试编辑是不同状态，不共用一个含混的 preview 标志。

## 3. 前端临时内容预览

目标：用户可以在真实页面里尝试文案，观察排版和大致效果，然后把满意的修改交给代码维护者落实。

**站长和其他访客拥有相同的页面试编辑能力，均不能通过网页保存线上内容。** 不检测站长身份，不构建隐藏写入权限。正式修改权限来自本地文件和 GitHub 仓库权限。

```text
代码中的基准内容
→ 当前页面内存中的临时覆盖值
→ 即时页面预览
→ 复制修改清单
→ 人工 / Codex 修改本地内容文件
→ 检查、提交、构建、部署
→ 新的正式内容
```

网页不能直接修改本机源代码或 GitHub 仓库。复制到剪贴板不代表已经保存、提交或上线。

### V1 可编辑范围

- 白名单内的可见文本：Hero 标题、副标题、说明；System Summary 标题与说明；三个视角的标题与说明；Production Proof 标题、说明及图注；Footer 普通展示文案。
- 单行或多行纯文本，支持中文、英文和普通标点。不解析 HTML、脚本或任意 Markdown。
- 默认提供明确的“试编辑”入口；打开后可选择字段并编辑，变化即时反映在页面。
- 编辑入口克制，不改变目标图的主要布局。进入编辑后才出现字段标记与面板。

不支持修改路由、URL、邮箱、资产路径、系统事实元数据、图节点标签/ID、图拓扑、状态、CSS、字体、动画参数、布局或图片；不提供上传、拖拽页面搭建、协同编辑、版本历史和内容发布。

试编辑中的任意文字不自动成为已核实事实。落实到代码前仍需检查命名、事实、贡献归属及文案规则。

## 4. 状态与组件契约

- 正式内容集中于有类型的本地内容文件；项目已有 `src/content/home.ts`，优先沿用，不另建重复来源。
- 基准内容只读。使用稳定字段 ID、标签、单行/多行类型及基准值构成字段注册表；字段 ID 不由显示文案派生。
- 客户端仅维护 `Partial<Record<EditableFieldId, string>>` 一类白名单覆盖值。显示值由覆盖值与基准值合成，支持空字符串，不用 `override || baseline` 吞掉空值。
- 不使用 localStorage、sessionStorage、IndexedDB、cookie、URL 或网络接口存储修改。临时值仅存在当前文档内存中。
- 关闭编辑面板保留当前临时效果；再次打开仍可继续编辑。刷新恢复正式内容。提供单字段恢复及“恢复全部”。字段改回基准值后从修改清单移除。
- 页面清楚显示“临时预览，刷新后恢复”；退出面板但仍有改动时保留简短的临时状态提示和恢复入口。
- 编辑状态与 Master Canvas reducer 分离。编辑文字不得重建图拓扑、丢失视图状态或重播整页启动动画。
- 不为编辑功能把整个页面标为 `use client`。采用有明确边界的客户端 Provider / 可编辑文本叶组件 / 面板；页面外壳及静态内容仍可在构建时生成。
- 基准文案应出现在预渲染 HTML 中，元数据始终取正式内容；临时预览不修改 SEO 或页面发布状态。

## 5. 复制修改清单

提供“复制修改清单”按钮，至少包含：

```json
{
  "schemaVersion": 1,
  "source": "src/content/home.ts",
  "changes": [
    {
      "fieldId": "hero.description",
      "label": "Hero 说明",
      "original": "基准文案",
      "modified": "临时文案"
    }
  ]
}
```

字段名为示例，实施时与现有内容结构建立明确映射。只有实际差异进入清单；中文、引号、换行和空值必须完整保留。

复制失败时显示可选择的只读文本供手动复制，不虚报成功；无修改时明确提示。无需添加导入、下载、GitHub API 或自动写文件能力。

落实清单前，Codex 核对字段存在且当前源值与 `original` 一致；若源文件已被其他工作修改，报告冲突，不盲目覆盖。

## 6. 编辑体验与动效

- 使用真实 button、label、input / textarea；支持键盘、清晰焦点、输入法和移动端。
- 编辑面板不得覆盖正在编辑的主要文本；窄屏采用适当的抽屉或文档流面板。
- 编辑期间降低或暂停干扰输入的 ambient / 自动入场动画，不锁死正常滚动。退出后遵循原生命周期和 reduced-motion 偏好，不积累额外 RAF / tween。
- 普通浏览状态保持 final.png 的视觉目标。编辑态采用同样的暖白、炭黑、细线语言，不复制完整 CMS 工具栏。
- 不以隐藏按钮、站长专用开关或浏览器角色字段冒充鉴权。

## 7. 静态构建与正式发布

- 使用 Next.js 静态导出；不增加 API routes、Server Actions、运行时鉴权、数据库、Draft Preview 或缓存刷新服务。
- 发布前根据实际 GitHub 仓库及站点 URL 确定 base path、静态资源、canonical 和工作流。不虚构域名或仓库。
- 本地修改内容文件、检查、Git 提交、构建、GitHub Pages 部署才构成正式内容更新。
- 完成首页开发和验证后可继续准备部署；缺少仓库、权限或站点配置时询问。文档修改本身不是已经部署。

## 8. 验收标准

首页原有视觉、响应式、Master Canvas、无障碍和性能要求不因新增试编辑而降低。对照 final.png，至少检查 390 / 768 / 1440px 视口；静态导出后使用静态服务器验证，而非只运行开发服务器。

导航验收：Header 和 EXPLORE / VIEW EVIDENCE 点击进入各自路由，不滚动替代；目标未完成时显示明确说明。验证直接访问、刷新、返回首页、浏览器前进/后退和 GitHub Pages 子路径。Master Canvas 预览切换不改变 URL；BACK TO TOP 仍为页内行为。

临时内容预览必须验证：

1. 任意访客可进入试编辑，无登录或身份差别。
2. 修改白名单字段即时反映，中文输入法、换行、空值正常；类似 HTML 的输入作为文本展示，不执行。
3. 关闭/重开面板保留当前页面临时值；单字段和全部恢复有效；刷新还原基准值。
4. 两个独立页面会话互不影响；输入不会触发内容写入网络请求，也不写浏览器持久存储。
5. 复制清单的字段、原文、新文完整正确，只含实际差异；复制失败有手动复制回退。
6. 文字编辑不重置 Master Canvas；快速切换视图、resize、键盘和 reduced motion 正常。
7. 构建和静态预览通过；预渲染 HTML 保有正式文案。关闭或不使用编辑器时，首页仍正常可读。
8. 只有修改本地源文件并重新构建/部署才更新正式内容；不将剪贴板复制称为保存成功。

自动检查覆盖关键状态生命周期、差异生成与转义、刷新恢复和静态构建。视觉对照与中文输入法等人工检查单独记录。未做的测试、缺失截图、未上线的状态必须明确报告。

## 9. 实施衔接

不要重建已有首页。先阅读当前代码并保留实施线程成果，复用 `src/content/home.ts`，小步添加字段注册表、临时覆盖层、编辑 UI、修改清单及针对性验证。优先确保静态首页与 Master Canvas 稳定，再集成试编辑；不借此增加后台或重新设计整站。
